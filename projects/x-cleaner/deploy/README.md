# X Cleaner 웹판

직접 고른 내 게시물·댓글만 삭제하고 내 리포스트만 취소하는 React 웹앱입니다. 기본 선택은 모두 꺼져 있고 실제 실행은 기본 비활성화 상태입니다. 아카이브와 전체 본문을 서버에 업로드하지 않습니다.

## 로컬에서 실행

```bash
conda activate min
cd ~/Desktop/x-cleaner/deploy
npm ci --cache .npm-cache
npm run dev
```

REDACTED_CONFIG_VALUE 에 접속합니다. Python 작업은 `min`을 사용하고 Node 의존성은 이 폴더의 `node_modules/`에 설치합니다. 로컬 개발 서버는 암호화 키를 자동 생성해 Git 제외된 `.env.local`에 권한 600으로 저장합니다. 키를 출력하지 않습니다.

1. ZIP/폴더를 파일 선택 창에서 선택합니다. ‘파일 없이 체험하기’는 가짜 데이터이며 실제 실행할 수 없습니다.
2. 삭제할 게시물·댓글·리포스트를 체크합니다. 필요하면 추가 보호할 링크/ID를 입력합니다.
3. ‘선택 목록 미리보기’에서 대상·보존·대상 밖 수와 결과 파일을 저장합니다. API 요청 없음.
4. 우측 상단 ‘API 설정’에서 본인의 Client ID 및 필요할 경우 Client Secret을 입력하고 화면의 콜백 주소를 X 개발자 콘솔에 정확히 등록합니다. Native/SPA는 공개 클라이언트, Web App은 비밀키가 필요한 confidential client입니다.
5. ‘X 계정에 연결’을 누릅니다. 운영자 앱을 사용할 때만 운영자의 사용 코드가 필요할 수 있습니다. 내 API 앱을 선택하면 해당 앱의 인증·크레딧으로 요청합니다.
6. ‘계정·선택 목록 검증’은 공식 API 조회로 비용이 발생할 수 있습니다. 검증 전에는 삭제하지 않습니다.
7. 사이트 운영자가 실제 실행을 활성화한 경우, 최종 확인 창의 문구를 정확히 입력하고 명시적으로 실행해야 요청을 시작합니다.

개발자 콘솔에서 앱 생성과 API 크레딧 구매는 X 공식 화면에서 진행해야 합니다. 앱 화면만으로 X의 계정·결제 절차를 대신할 수는 없습니다.

## 개인정보와 보안

- 아카이브 파싱은 브라우저에서 수행합니다. 숫자 ID는 lossless-json으로 읽고 문자열로 유지합니다. eval을 사용하지 않습니다.
- ZIP 중앙 디렉터리의 위험 경로·중복·심볼릭 링크를 검사합니다. ZIP 128 MiB, 관련 데이터 파일당 32 MiB, 합계 96 MiB 제한. 더 큰 ZIP은 압축을 푼 폴더 또는 개인용 CLI로 읽으세요. ZIP64/분할 ZIP은 폴더로 입력합니다.
- 작업 ID·선택 항목·결과는 해당 브라우저 IndexedDB에 저장합니다. 보존 ID 누락은 미리보기에서 전체 실행을 차단합니다. 원본에 없는 마지막 분할 파일의 누락까지 증명하지는 못합니다.
- 사용자가 입력한 API 설정은 사용자별 암호화된 HttpOnly 쿠키로 24시간 보관합니다. 빈 Secret 입력은 기존 본인 설정을 유지합니다. 운영자 앱을 다시 선택하면 본인 설정과 로그인 세션을 지웁니다.
- OAuth state와 S256 PKCE를 검증합니다. 토큰은 브라우저 JavaScript·응답 JSON·URL에 노출하지 않고, 최대 2시간 AES-256-GCM 암호화된 HttpOnly/SameSite 쿠키로 보관합니다. HTTPS 배포에서는 Secure를 설정합니다. offline.access/refresh token은 요청하지 않습니다.
- Vercel 서버는 X API 호출 중 설정·토큰을 복호화합니다. ‘서버가 토큰을 볼 수 없다’는 구조는 아닙니다. 사이트 운영자의 서버/암호화 키 접근 권한이 신뢰 경계입니다.
- Origin 및 Sec-Fetch-Site 확인, JSON 및 64 KiB 입력 제한, CSP, 프레임 차단, no-store 응답을 적용합니다. 운영자는 플랫폼 요청 로그에서 OAuth 콜백 query 및 요청 body를 수집하지 않도록 해야 합니다.
- 검증한 선택 목록을 서버가 암호화해 승인합니다. 사용자·보존·종류·작성자·수정 이력·리포스트 관계를 요청 직전에 다시 검사합니다. 선택/보존 문구 변경은 UI에서 이전 승인을 무효화합니다.
- 수정 이력이 여러 버전인 게시물은 웹판에서 차단합니다. 개인용 엔진으로 전체 이력을 확인하세요. 작성 후 1시간 이내 게시물도 실행을 차단합니다.
- 리포스트는 내 아카이브 항목 ID가 현재도 내 리포스트임을 검증하고 원본 ID로 내 리포스트 취소만 요청합니다. 이미 없어진 항목 대신 새 리포스트를 취소하지 않습니다.
- 좋아요·DM·팔로우 요청 경로는 없습니다. 404/조회 불가는 이미 삭제되었다고 확정하지 않고 별도 `unavailable` 상태로 기록합니다.
- 브라우저 실행 잠금, 요청 전 기록 저장, 완료 항목 제외, 429 서버 시각 대기 및 최대 3회 시도(최초 포함)를 적용합니다. 인증·권한·결제 오류는 중단합니다. 브라우저를 닫으면 서버 작업은 계속 돌지 않습니다.

## 이어하기

같은 브라우저와 사이트에서 동일한 아카이브를 다시 선택합니다. 저장된 선택과 보존 목록을 복원하고, 성공/조회 불가 항목을 제외해 X에 다시 연결하고 검증합니다. 승인 목록은 만료될 수 있습니다. 모호한 응답/중간 종료 항목은 검증 후 명시적으로 다시 확인합니다. 브라우저 기록을 지우거나 다른 기기로 옮기면 IndexedDB 상태는 복원되지 않습니다. JSON 내려받기는 감사용이며 자동 실행 입력으로 읽지 않습니다.

## Vercel 배포

Vercel 프로젝트 Root Directory를 **deploy**로 지정하세요. 현재 소스는 Vite 정적 파일과 `api/*.js` Node 함수를 함께 배포하도록 구성했습니다. 전체 `personal/` 폴더·아카이브·토큰을 업로드하지 마세요.

환경변수는 `.env.example` 참고:

| 변수 | 용도 |
| --- | --- |
| `APP_ORIGIN` | 고정된 HTTPS 배포 주소, 마지막 `/` 없이 설정 |
| `SESSION_ENCRYPTION_KEY` | 웹 프로젝트 전용 64자리 hex 암호화 키; 서버 전용 |
| `X_CLIENT_ID`, `X_CLIENT_SECRET` | 운영자 앱을 제공할 경우 설정; 사용자별 API 설정은 앱 화면에서 가능 |
| `ACCESS_CODE` | 운영자 앱 사용 코드를 제공할 경우 16자 이상 |
| `PUBLIC_OAUTH_ENABLED=false` | 운영자 앱의 기본 인증은 사용 코드 필요; 공개 인증 전 비용/남용 제한 준비 |
| `EXECUTION_ENABLED=false` | 기본값. 실제 쓰기를 열기 전 실제 인증/권한 검증 필요 |

Vercel 계정 로그인, 프로젝트 연결, 배포 도메인과 서버 암호화 키는 배포 운영자가 준비해야 합니다. 공개 방문자가 운영자 키를 바꾸는 설정 페이지는 만들지 않습니다. 운영자는 Vercel 환경변수 화면에서 관리하세요. 환경변수 이름에 `VITE_`를 붙이면 브라우저 번들에 노출될 수 있으므로 비밀값에 사용하지 마세요.

X는 현재 크레딧 기반 사용량 요금제를 안내합니다. 조회도 비용이 발생할 수 있으며 DELETE 자체의 단가는 콘솔에서 확인해야 합니다. 일반 게시물 삭제 및 리포스트 취소의 문서상 사용자 요청 제한은 각각 50회/15분이며 실제 응답 헤더가 우선입니다. 공개 운영에서 앱 크레딧 소비를 제한하려면 X 콘솔의 사용량 관리와 Vercel 방화벽 제한을 설정하세요. 현재 앱에는 데이터베이스 기반 사용자별 과금/할당량 시스템은 없습니다. 사용 코드는 공유할 수 있으므로 사용자별 제한을 대신하지 않습니다.

Vercel 함수에서 오래 대기하지 않고 브라우저가 대기 후 짧은 요청을 보내도록 구성했습니다. Vercel Hobby는 개인·비상업적 용도이며 상업 운영에는 해당 플랜 조건을 확인하세요.

```bash
npm test
npm run build
```

보안 모의 테스트는 가짜 HTTP 응답만 사용합니다. 실제 X 인증·배포 환경을 검증한 것과 구분하세요. 개발 환경의 브라우저 제어 권한이 없어 웹 시각 검증은 아직 하지 못했습니다.
