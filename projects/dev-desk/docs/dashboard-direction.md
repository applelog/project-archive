# 개인 개발 대시보드 — 방향 초안

작성: 2026-09-24. 상태: 설계 기록. 현재 구현과 실행 방법은 [README](../README.md)를 따른다. 초기 Tauri 제안은 로컬 Swift/Xcode 환경을 확인한 뒤 네이티브 SwiftUI로 변경했다.

## 목적과 판단

개발을 시작할 때 세팅 방법과 스킬 사용법을 다시 찾는 시간을 줄인다.
스킬 이름을 모으는 것만으로는 사용 순서를 판단하는 부담이 남는다.
따라서 작업 상황 → 필요한 준비 → 스킬 적용 순서 → 복사할 지침으로 연결한다.
첫 단계의 성공 기준은 자주 하는 작업 하나에서 외부 검색 없이 지침을 검색·편집·조합하고 한 번에 복사하는 것이다.
전체 목표에는 AI가 지침을 추가하는 경로, 스킬 활동 확인, AI 도구별 사용량·잔여 한도 조회, 비용 시각화, 맥의 배터리·전력·자원 상태를 포함한다.
제품 목적은 개발 중 필요한 지침과 작업·자원 상태를 한 앱에서 확인하는 것이다. CLI 자체를 대체하는 터미널은 현재 범위로 확정하지 않는다.

## 확정된 사용 맥락

- 사용 도구는 Google Antigravity(agy)와 Codex이며 주로 CLI에서 사용한다.
- 두 도구 모두 구독으로 사용한다. 사용자가 agy 관련 구독으로 제공한 화면에서 Google AI Pro (5 TB)를 확인했다. Codex는 ChatGPT Plus를 사용한다.
- 사용자 제공 Google Play 구독 화면 기준(2026-09-24): 다음 결제는 2026-10-12, 7,300원. 청구 일정은 2026-10-12부터 월 7,300원, 2027-08-12부터 월 29,000원이다. 2026년 8월부터 구독했다는 표시가 있다. 지난 결제액과 할인 시작일은 이 화면만으로 추정하지 않는다.
- 위 구독 정보는 사용자 제공 화면에서 확인한 값이며 자동 동기화한 값이 아니다. 이 화면은 토큰 사용량·잔여 한도나 CLI의 구독 연결 상태를 증명하지 않는다.
- 사용자는 정보가 풍부한 화면과 사용량·금액·배터리 상태의 시각화를 원한다.
- 2026-09-24 로컬 확인: codex와 agy 실행 파일이 존재한다. agy 도움말은 log-file과 stream-json 출력 옵션을 제공한다. 이는 관측 경로 후보이지 구독 한도 조회 지원의 증거가 아니다.
- Codex 설치 링크는 0.156.1이며 app-server 도움말을 확인했다. 실제 계정 응답과 별도 CLI 세션의 관측 범위는 아직 검증하지 않았다.

## 확인한 사실

- 최초 확인 시 작업 폴더는 비어 있었으며 기존 앱과 패키지 설정이 없었다. 이후 이 폴더에 SwiftUI 앱 첫 버전을 구현했다.
- 로컬 karpathy-guidelines, Superpowers brainstorming/writing-plans, emil-design-eng, apple-design을 읽었다.
- Superpowers 파일은 로컬 임시 플러그인 저장 경로에서 발견했다. 파일 존재만으로 현재 도구에서 활성화되어 있다고 표시하지 않는다.
- https://github.com/emilkowalski/skills 에서 emil-design-eng 및 apple-design 항목을 확인했다.

## 접근 방식 비교

| 방식 | 이점 | 비용과 한계 |
| --- | --- | --- |
| 사용법·세팅 가이드 웹앱 | 작게 만들 수 있으며 검색과 반복 입력을 줄임 | 실제 설치 상태와 문서 내용의 차이를 사람이 확인해야 함 |
| 로컬 스킬 파일을 읽는 웹앱 | 현재 파일을 바탕으로 목록과 원문을 확인 가능 | 로컬 서버, 허용 경로, 파일 갱신 처리 필요 |
| 세팅 명령까지 실행하는 도구 | 실제 준비 과정도 단축 | 도구별 실행 방식, 권한, 실패 복구까지 설계 필요 |

초기 가이드 웹앱 추천은 요구 확장에 따라 변경했다. 실제 구현은 설치된 Xcode와 macOS 네이티브 API를 활용하는 SwiftUI 앱을 선택했다.
로컬 기능과 화면을 연결하되, 사용량 연동이나 실행 상태가 구현되지 않은 항목은 그대로 미확인으로 표시한다.
명령 자동 실행과 다른 앱 입력창에 자동 붙여넣기는 아직 요청 의미가 확정되지 않아 기능 범위로 확정하지 않는다.

## 사용자 요구와 기능 경계

| 영역 | 계획할 기능 | 확인·설계 조건 |
| --- | --- | --- |
| 사용법 보관함 | 검색, 바로 읽기, 복사, 추가·수정·삭제 | 실제 사용할 지침으로 흐름 검증 |
| 지침 묶음 | 여러 지침 선택, 순서 변경, 합친 내용 미리보기, 전체 복사 | 원문 수정 시 묶음에는 최신 내용을 반영하고 수정됨을 표시 |
| AI가 지침 추가 | 사용자가 지정한 보관함에 AI가 항목을 추가하고 앱에 반영 | 첫 후보는 로컬 Markdown 파일과 앱의 다시 읽기. 별도 AI API 호출이나 MCP 서버가 필수는 아님 |
| 스킬 활동 | 파일 존재, 관측된 로드·호출, 관련 오류와 최근 기록 | 도구별 공식 이벤트·로그로 관측 가능한 항목만 표시 |
| 사용량 | 도구·계정별 사용 토큰, 비용, 제공되는 잔여 한도와 초기화 시점 | API 과금, 구독 한도, 대화 컨텍스트 사용량을 별도 지표로 표시 |
| 맥 상태 | 배터리 잔량·전원 상태·예상 사용 가능 시간, 배터리 추이, CPU·메모리 상태 | 센서와 공식 API가 제공하는 범위에서 표시. 정확한 종료 시각으로 단정하지 않음 |
| 전력 | 지원 시 현재 전력과 추이, 충전·방전 상태 | 배터리 방전 전력·충전 입력·부품 전력을 구분. 앱별 정확한 W는 지원 검증 전 약속하지 않음 |

사용자 편집과 AI 편집에는 같은 저장 규칙을 적용한다. 항목 ID를 유지하고 저장 전 변경 충돌을 확인하며 이전 내용을 복구할 수 있게 한다.
외부 파일이 편집 중 바뀌면 조용히 덮어쓰지 않고 두 내용을 비교할 수 있어야 한다.
지침 묶음은 항목 ID와 순서를 참조한다. 원문 삭제 시 누락을 표시하고 복사 전 확인할 수 있게 한다.
AI가 만든 항목에는 작성 출처를 남긴다. 기존 사용자 지침의 변경은 변경 내역을 보존한다.
API 자격 증명이 필요하면 macOS의 보안 저장소에 보관하고 지침 파일에 넣지 않는다.

## 활동·사용량에 대한 사실 경계

- 스킬은 지침 문서일 수 있다. 설치 여부, 로드 여부, 호출 관측, 지침 준수 평가를 같은 상태로 취급하지 않는다.
- 호출 증거가 없으면 미확인으로 표시한다. 로그에 없다는 이유만으로 실패 또는 비활성으로 단정하지 않는다.
- 스킬 지침을 제대로 따랐는지는 결과물·검증 기록을 통해 평가한다. 호출 이벤트만으로 정상 동작을 보증하지 않는다.
- 활동 기록에는 도구와 세션, 발생 시각, 확인 근거를 연결한다. 수집 중단·권한 오류·지연을 숨기지 않는다.
- 사용량에는 출처, 집계 기간, 마지막 갱신 시각, 공식값/추정값을 함께 표시한다.
- 지원되지 않는 잔여 한도를 사용량으로 역산하거나 0으로 표시하지 않는다. 공식 화면 연결 또는 미지원으로 표시한다.
- 로컬 관측값은 다른 기기와 미수집 세션까지 포함한 계정 전체 사용량으로 표시하지 않는다.
- 실시간 범위는 도구별 수집 주기와 제공 지연을 확인한 뒤 확정한다.
- 구독료, 확인된 추가 결제, API 요금 기준 환산액은 별도 표시한다. 환산액을 실제 청구액 또는 절약액으로 표시하지 않는다.
- 구독 비용에는 서비스명, 다음 결제일·결제액, 효력 시작일별 요금 일정을 보관한다. 다음 결제액과 할인 종료 후 금액을 구분하고 과거 기간에 현재 단가를 소급 적용하지 않는다. 직접 입력·화면 확인·자동 조회의 출처와 확인 날짜를 남기며 사용자가 수정할 수 있게 한다.
- 환산액은 모델, 입력·캐시·출력 토큰 구분, 적용 가격과 가격 기준일이 확인된 구간만 계산한다. 정보가 부족하면 산출 불가 또는 부분 집계로 표시한다.
- 누적 사용량 이벤트를 단순 합산하지 않는다. 세션·이벤트 식별자로 중복을 제거하고 기간별 증분을 계산한다.
- 계정 전체 사용량과 세션별 로컬 집계는 범위가 다를 수 있으므로 같은 총합에 중복 포함하지 않는다.
- 배터리는 전원 연결, 충전 중, 방전 중, 추정 불가를 구분한다. 충전 상태의 0분 응답을 즉시 종료로 해석하지 않는다.
- 배터리 예상 시간은 OS 값을 우선한다. 독자 추정이 필요하면 충분한 방전 관측 구간에서만 산출하고 부하 변화에 따른 변동을 표시한다.
- 실제 전력 W와 에너지 Wh를 구분한다. 앱별 상대적 에너지 영향도를 정확한 소비 전력 W로 변환하지 않는다.
- 대시보드의 수집 자체가 과도한 부하를 만들지 않도록 이벤트 기반 갱신을 우선하고 화면이 숨겨지면 그래프 렌더링과 불필요한 폴링을 줄인다.

## 제안하는 첫 화면

- 왼쪽: 개요 / 지침 보관함 / 지침 묶음 / AI 활동 / 사용량·비용 / 맥 상태.
- 상단: 통합 검색. 이름뿐 아니라 작업 설명으로도 찾을 수 있게 한다.
- 기본 개요 화면: 계정별 한도와 초기화 시점, 배터리·예상 사용 시간, 관측 중인 세션, 자주 쓰는 지침 묶음을 요약한다.
- 중간: 도구별 사용량 추이와 배터리·전력 추이. 값이 없으면 수집 대기 상태를 표시하며 가짜 데이터를 채우지 않는다.
- 하단: 최근 활동·오류·완료 기록과 지침 바로가기.
- 지침 보관함: 선택한 분류의 목록을 제목과 용도가 읽히는 행 형태로 표시한다.
- 상세: 언제 쓰는지, 선행 준비, 사용 순서, 복사할 지침, 원문 출처.
- 복사 동작: 성공한 경우에만 완료 표시. 실패하면 직접 선택해서 복사할 수 있도록 텍스트 유지.

필수 데이터는 제목, 용도, 사용 환경, 준비 사항, 지침, 원문 출처, 확인 날짜다.
검증하지 않은 명령이나 스킬 호출 문법을 사용 가능한 명령으로 표시하지 않는다.
가이드 복사와 실제 스킬 실행을 화면에서 명확히 구분한다.

## 디자인 방향

- macOS 설정 화면처럼 익숙한 탐색 구조와 일정한 상세 위치를 사용한다.
- 중립적인 배경, 시스템 글꼴, 명료한 글자 대비, 절제된 강조색으로 정보 위계를 만든다.
- 반투명 효과는 탐색 영역에 제한하고 본문과 코드의 가독성을 우선한다.
- 검색·키보드 이동은 즉시 반응한다. 상태 피드백에만 짧은 전환을 적용한다.
- 키보드 포커스를 보이게 하고 색상 외에 텍스트로도 상태를 전달한다.
- 모션 감소 설정에서는 이동 효과를 제거한다. 좁은 화면에서는 목록에서 상세로 이동한다.
- 기본 화면은 업무 상태를 빠르게 파악하는 개요로 구성한다. 검색과 지침 복사는 상단에서 항상 접근 가능하게 두고 지표 클릭 시 상세 화면으로 이동한다.
- 한도는 기간이 명시된 수평 막대, 사용량은 일별 막대와 추이, 배터리는 시간별 선 그래프로 표시한다. CPU와 배터리처럼 단위가 다른 값은 같은 축에 섞지 않는다.
- 실제값·추정값·미확인과 마지막 갱신 시간을 표시하고, 차트에는 텍스트 값과 키보드로 접근 가능한 상세를 제공한다.
- 장식용 차트, 별도 서비스 로그인, 클라우드 동기화는 현재 요구에 필요하지 않아 제외한다. AI 도구 연결에 필요한 인증은 별개다.

## 검증 기준

- 대표 작업에 필요한 지침을 검색하고 상세에서 복사할 수 있다.
- 검색 결과 없음, 복사 실패, 긴 지침도 사용 흐름을 막지 않는다.
- 모든 초기 가이드에는 출처와 확인 날짜가 있다.
- 키보드로 검색·선택·복사할 수 있고 좁은 화면에서 본문이 잘리지 않는다.
- 로컬 연동을 선택하면 파일 누락과 읽기 실패를 정상 상태와 구별한다.
- 편집 후 다시 실행해도 지침이 유지되며 앱·AI의 동시 수정으로 내용이 소실되지 않는다.
- 선택한 지침만 지정한 순서로 조합되며 복사 전에 결과를 볼 수 있다.
- AI가 지정 보관함에 만든 올바른 항목이 앱에 반영되고 잘못된 형식은 수정 가능한 오류로 표시된다.
- 활동 표시는 실제 관측 기록과 연결된다. 파일만 존재하는 스킬을 실행 중으로 표시하지 않는다.
- 사용량 연동이 끊기면 이전 값의 시각과 갱신 실패를 표시한다. 미지원 잔여량은 수치로 꾸미지 않는다.
- 구독 금액과 API 환산액이 구분되며 기간·모델·가격 기준과 집계 범위가 일치한다.
- 전원 연결·해제와 잠자기 복귀 시 배터리 표시가 갱신되고 추정 불가를 0분으로 표시하지 않는다.
- 같은 사용량 이벤트를 다시 수신해도 총량이 늘어나지 않는다. 수집 공백은 그래프에서 정상 관측처럼 이어 붙이지 않는다.

## 적용 자료

- Karpathy: 가정을 드러내고, 검증 가능한 목표와 최소 범위를 정한다.
- Superpowers brainstorming: 요구 확인, 접근 비교, 설계 검토 후 구현 계획으로 전환한다.
- Superpowers writing-plans: 확정된 설계를 실행 가능한 작은 작업으로 나눈다.
- Emil: 자주 쓰는 작업에 불필요한 모션을 넣지 않고 피드백을 명료하게 한다.
- Apple design: 익숙한 구조, 사용자 통제, 정보 위계, 즉각적인 반응을 우선한다.
